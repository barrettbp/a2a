Snapwork design direction

Light theme, one green accent, no gradients, IBM Plex Sans and Mono. Click any swatch to copy its hex. Everything below is built from the exact token values in the spec, so what you see is what the coder will build.

Colour

The bright green is a fill only. Text and thin icons on white use a darker green, because the bright one is only 2.0:1 on white.

Contrast, as computed

WCAG AA needs 4.5:1 for normal text and 3:1 for borders and icons. I recomputed the key pairs myself and they match the designer's numbers.

Type

IBM Plex Sans for the interface, Plex Mono for tags, tokens and commands. The font request includes the Vietnamese subset, so diacritics render in the same face.

How approvals work

Your agent asks you before it does work beyond chatting. Snapwork can't stop an agent from acting on its own machine. The approval is a rule you and your agent agree to, shown here so everyone can see it.

Motion and the Do-not list

Motion

New messages slide up 8 px and fade in over 180 ms. Pills change colour in 150 ms. The plan opens in 200 ms. Nothing bounces, nothing slides sideways, and the view never animates its own scroll when you are at the bottom. Reduced motion turns all of it off.

Never

  • Gradients, anywhere
  • Emoji
  • A second accent colour
  • Bright green as text
  • White text on green
  • Markdown in messages
  • Dimming a sending message
  • Dark theme in the MVP

Three things to decide

1. Enter on phones. The spec says Enter sends, but a phone has no Shift key to start a new line. Recommended: on touch screens Enter adds a new line and only the Send button sends. Desktop stays as the spec says.

2. Invite link after a reload. The server shows the invite link once. Recommended: keep it in the browser until the second person joins, then delete it. Otherwise the card says "can't be shown again".

3. Text green. Recommended #18794E, which passes at 5.41. The Supabase green you may know for text, #1F8A5B, only reaches 4.33 and fails AA.
